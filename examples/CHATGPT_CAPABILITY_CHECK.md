# 聊天端能力验收提示词

先完成本地配置、预检和监听器启动。替换下方仓库与项目 ID，把下面这段要求发给准备使用的 ChatGPT 聊天。它授权一次“不改项目文件”的交接验证；只有真实工具结果才能作为证据。

> 为仓库 `YOUR_GITHUB_NAME/YOUR_PROJECT_SHARE`、分支 `main`、项目 ID `demo` 检查当前聊天的 Git 交接能力。
>
> 1. 列出当前实际可调用的读取、更新仓库文件工具；不要根据模型名称或连接图标推断可用性。
> 2. 用工具读取根目录 `HANDOFF.md`，报告项目 ID、请求数、当前文件 blob SHA 和分支提交 SHA。如果读取失败，停止派发，给出失败信息，结论为“无法读取”。
> 3. 若没有文件更新工具，结论为“手动交接”：可以分析和生成请求，但需要用户或 Codex 提交；不声称已经唤醒任务。
> 4. 若有更新工具，我授权你追加一次不修改项目文件的验收请求。新建唯一 request_id 和唯一回复标记；任务要求“不使用工具、不修改项目文件，只回复该标记”。遵循 CHATGPT_INSTRUCTIONS 的查重和当前 SHA 更新规则。记录真实写入工具结果；写入不明时重新读取远端，不更换 ID 重发。
> 5. 再次读取同一请求。只有看到真实 Codex 回执、任务 ID、轮次 ID 以及预期标记，才结论为“自动交接已验证”。若只写入成功但尚无回执，结论为“写入已验证，执行未验证”。监听器未运行时不能判定模型不兼容。
> 6. 最后输出能力报告：聊天产品与所选模型（不可取得时写未知）、仓库、读取工具、更新工具、request_id、写入提交、回执状态、验证时间、结论。不要包含令牌或私人文档正文。

本地 `gh` 的读写结果不能替代聊天端的这份证据。每次更换聊天产品、连接、账号或工作区后重新验收。只切换模型时先检查工具仍可用；没有证据时沿用“未验证”，不默认兼容。
